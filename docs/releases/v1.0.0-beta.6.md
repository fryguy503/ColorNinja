# ColorNinja Studio v1.0.0-beta.6

Windows x64 prerelease. Extract the complete
`ColorNinja-1.0.0-beta.6-windows-x64.zip` and run `ColorNinja.exe`.

Beta 6 addresses the Beta 5 application/HueForge review:

- Preserve rare diagonal strokes, curves, lettering, and eyes during downsampled
  analysis. Isolated speckles still have a rejection control.
- Stack and guide reports always use CIELAB for fields labeled Delta E76.
  Optimization scores have separate fields with working-space units.
- Repeated RGB colors can use a later height to reduce boundary jumps, retaining
  one matching height per RGB for HueForge Color Match compatibility.
- Refine several different filament orders independently of Preserve details.
  **Search effort → Refine** adds run insertion, deletion, splitting, merging,
  and transfers into/out of the base allocation.
- **Reduce layer show-through** scans every pixel for boundaries and accounts
  for export width and mesh spacing. An explicit working-color-score tolerance
  limits the tradeoff. Automatic depth also has a configurable tolerance.
- **Visualize stack** adds image-linked layer selection, height boundaries,
  intermediate-color exposure, an approximate surface, and HFP coverage.
  Step statistics use all pixels; the displayed grid is resolution limited.
- **Compare results** finds color, boundary, swap, and depth alternatives and
  saves up to four comparison thumbnails across sessions. **Compare without**
  measures the effect of excluding a selected spool. Required constraints can
  make fewer swaps infeasible. These are found plans, not guaranteed optima.
- Require spools, a base, or a final filament using stable identities. Missing,
  filtered, over-budget, or physically unused required spools produce an error.
  Guided includes constrained spools as references.
- Protect RGB colors within the existing budget. Shift-click a result swatch
  to add one. In filament modes these are weighted analysis targets, subject
  to the reachable print palette.
- Guided explains source → guided output → physical reference and offers a
  transition to Global stack to test a common printable order.
- Reuse unchanged smoothing, analysis, optical candidates, and completed results.
  Export-only changes reuse rendered pixels. Geometry changes invalidate stack
  optimization when show-through reduction is enabled.
- Record calibration provenance and inspect fixed-stack TD sensitivity without
  changing the physical model. See [the swatch protocol](../calibration.md).

## Blended Mesh Core TDs

Following feedback from HueForge, **Export → HueForge project → Mesh core → Tuned
image colors (recommended)** is now the default and fits virtual IMAGE TDs to
chosen image heights. It also
tries a smaller IMAGE core based on the physical blend path. Selection minimizes
required disables, then entries. Later equal colors do not need blanket disables;
a conflicting earlier height may still need one.

The stack map reports virtual TD range, entries, and disabled-layer counts.
The physical Color Core, real filament TDs, reduced image, and selected layer map
remain unchanged. This option does not recreate gradients already removed by
reduction; retain enough output colors for that task. Older **Match planned layers**
settings, presets, profiles, and projects upgrade automatically. Saved project
Mesh Core displays refresh without reprocessing the image. Export a new HFP and
reopen it in HueForge to replace an existing 0.01 TD core. **Flat image colors (legacy)**
retains the old export behavior as an explicit choice; **Use filament blends** remains available.

Native HueForge 0.9.4.3 checks returned zero layer mismatches and zero physical RGB
channel error. A 480×64 gradient used four Mesh Core entries instead of fifteen;
the 3750×4688 illustration eliminated twenty disables. These are tested software
compatibility results, not measurements of printed color.
