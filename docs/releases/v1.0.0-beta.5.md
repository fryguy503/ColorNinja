# ColorNinja Studio v1.0.0-beta.5

Global Stack gains an optional **Reduce layer show-through** setting for detailed
images whose mesh reveals unwanted intermediate colors around outlines and small
shapes. Download **ColorNinja-1.0.0-beta.5-windows-x64.zip**, extract the entire
folder, and open **ColorNinja.exe**.

- Enable **Global stack > Layers > Reduce layer show-through**, refresh the
  preview, and export a new HueForge project using **Color Match / Match planned
  layers**.
- Stack planning considers which source colors touch, favoring smaller height
  differences and fewer unrelated intermediate colors along those boundaries.
  It can change filament order and layer allocation while retaining the chosen
  filament, run, and depth budgets.
- The option starts off and is saved with projects, presets, and settings
  profiles. It works with either Preserve details setting and with optional
  filament returns. Automatic depth uses the combined color and boundary score
  when this option is enabled.
- The stack summary reports the estimated average height step across sampled
  color boundaries. The CLI equivalent is `--hueforge-reduce-show-through`.

This is a bounded planning heuristic, not a mesh preview or a guarantee of better
print appearance. It may trade color accuracy for cleaner boundaries. Very fine
details can be missed by sampling, and ColorNinja's flat preview does not display
the slopes between heights. Compare the actual HueForge mesh before printing.
See the [HFP guide](https://github.com/fryguy503/ColorNinja/blob/v1.0.0-beta.5/docs/hueforge-project.md)
for details.

Validation covers 112 Go tests, eight frontend tests, TypeScript/Vite, formatting,
Go vet, and the Windows production build. A controlled three-color fixture
reduced its mean boundary height step from 0.154 mm to 0.080 mm without color
error, including automatic-depth and detail-preservation combinations. UI checks
confirm the new control and preview invalidation. Installed HueForge 0.9.4.3
color-matching routines and shader checks matched 17,580,000 exported pixels
with zero layer-assignment or physical color-channel mismatches. These checks
validate color/height compatibility, not the rendered triangulated surface or
physical print quality.

The desktop build is unsigned and requires Microsoft Edge WebView2. Python,
Node.js, and Go are not required to run it. Native Windows file-dialog acceptance
testing and physical print validation retain the previous beta's limitations.
