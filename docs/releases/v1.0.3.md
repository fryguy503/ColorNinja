# ColorNinja Studio 1.0.3

Image processing now makes better use of multiple CPU cores, and Side by side
view can swap the Original and Result panes.

## Faster processing

Color Match evaluates independent stack candidates, complete-stack refinements,
and layer-thinning trials in parallel. Palette-cluster assignment also uses
multiple cores. Smoothing and pixel mapping now scale beyond their previous
eight-worker ceiling when the workload allows it.

Concurrency adapts automatically to available CPU capacity, workload size, and
estimated working memory, with a maximum of 16 workers. Small jobs stay small;
deep stacks and wide searches reduce concurrency to control additional memory.
Small CPUs retain their available concurrency, and larger CPUs reserve capacity
for the desktop. Cancellation waits for workers to finish before buffers are
reused. Matching calculations, color budgets, and print constraints are preserved.

On the tested Windows workstation, a Color Match benchmark improved about 1.7x
with two available CPUs, 2.7x with four, and 3.4x with eight. These are CPU-limited
workstation measurements, not guarantees for other images or older hardware.
See [performance measurements and memory limits](https://github.com/fryguy503/ColorNinja/blob/v1.0.3/docs/performance.md).

## Swap comparison panes

In **Side by side** view, click the two-arrow **Swap original and result panes**
button beside **1:1** to reverse the images. Click it again to restore their
original positions. Labels and color counts move with their images, linked zoom
and pan are retained, and swapping does not rerun image processing. The button
supports keyboard activation and announces its pressed state.

## Validation

Checks cover identical processing results across CPU limits 1, 2, 4, 8, and 32,
exact weighted-cluster arithmetic, cancellation, worker/memory limits, cache
reuse, and serialized progress. Seven workflow fixtures matched outputs captured
before parallelization. The Windows engine and studio suites passed the race
detector. Browser acceptance checks pane order, images, zoom/pan, keyboard
activation, and unchanged processing state. The release matrix builds and
verifies extracted packages on all five supported platforms.

Packages have no publisher signature; macOS builds are not notarized. Native
window/file-dialog, minimum-spec endurance, and clean-machine acceptance remains
open. Software checks do not establish physical print accuracy.
