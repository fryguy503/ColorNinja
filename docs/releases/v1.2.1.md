# ColorNinja Studio 1.2.1

## Save and export once

When the native Save As dialog confirms replacing an existing file, ColorNinja
now uses that approval instead of asking again. This applies to project saves,
settings-profile saves, and image, palette, layer-map and HueForge exports.

Approval covers only the exact filename selected in the dialog. If ColorNinja
adds an extension or needs to replace a companion project/profile file, it still
asks about that separate file. New files retain protection against accidental
overwrites, and declining or closing a confirmation cancels the operation.

This patch includes all [1.2.0 features](https://github.com/fryguy503/ColorNinja/releases/tag/v1.2.0),
including TD1/S devices, filament-library management and browser/file profile imports.

## Validation

Regression tests cover exact-path approval, new-file protection, changed
extensions, companion files, rejection and dialog errors. Release checks cover
Go and frontend tests, formatting, production builds, Go vet, dependency audits,
compiled-app browser acceptance and extracted packages. Native dialog behavior
was checked against the installed Wails implementation; full native-window
acceptance remains separate from these software checks.
