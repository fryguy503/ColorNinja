# ColorNinja Studio 1.2.2

## Fewer unnecessary filament switches

Color Match could retain short filament runs with no visible surface pixels,
including a buried color return that added two unnecessary switches. Normal
preview adjusted run lengths without trying run merges, and automatic depth
kept at least one layer in each run. A direct merge could also appear slightly
worse until the remaining layer allocations were adjusted.

Both Normal preview and Deeper refinement now try merging redundant runs.
The planner checks simpler schedules with adjusted layer allocations and favors
fewer runs when scores are equal. Every accepted simplification recalculates
the physical blends, preserves the existing color and filament constraints,
and has no worse optimization score. Automatic depth then uses your saved
depth allowance to compare the simpler plans.

A reproduced project went from eight runs and 22 image layers to six runs and
20 image layers under its saved settings. Every remaining run after the base
contributes visible pixels. Results depend on the image, filaments and settings:
buried layers that are needed to produce the colors above them are retained.

Open an existing project and refresh its preview to generate a new plan, then
save and export again. Saved previews retain their original plan until refreshed.

This patch includes all [1.2.1 fixes and features](https://github.com/fryguy503/ColorNinja/releases/tag/v1.2.1).

## Validation

Regression tests cover merge-and-reallocate planning in both search modes,
equal-score run removal, required spools, optically necessary buried layers,
determinism and cancellation. Release checks cover Go and frontend tests,
formatting, production builds, Go vet, dependency audits, compiled-app browser
acceptance and extracted packages across all five platforms. Software checks
do not establish physical print appearance or native file-dialog acceptance.
