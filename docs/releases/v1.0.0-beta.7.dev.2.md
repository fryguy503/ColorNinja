# ColorNinja v1.0.0-beta.7.dev.2

Local Windows x64 development build. Published Beta 7 is unchanged.

**Optimize layer order** replaces the material-reduction checkbox. It automatically
considers color families, spatial coherence, surrounding colors, actual assigned
heights, and boundary transitions. Related foliage shades are grouped; compact
accents can rise above dominant colors without selecting a foreground color or
manually arranging spools. Solid volume remains a diagnostic.

The search tries multiple matching accent spools, relocates whole runs, and
checks repeated-run mappings. Overall and per-family color guards apply to the
final result. The Layers panel reports the inferred preference and identifies
partial placement instead of implying that a late red spool has lifted every red.

Enabling starts with a 5% minimum working-color-score allowance. Advanced can set
a stricter value afterward, including 0%. Dev.1 material-enabled settings migrate
to this automatic preset; explicit new-format values remain authoritative.

This is a color/region heuristic, not semantic depth reconstruction. Shared image
colors retain one global height. Inspect the exported result in HueForge before
printing. See [the optimization overview](../print-optimization.md) for the original
feedback, implementation, comparison methods, and earlier experiment results.

On the original Totoro test, Normal preview automatically moved skirt reds from
1.04 mm to 3.20 mm while Totoro's gray median became 2.00 mm. Whole-image color
RMS improved from 13.63 to 13.39, and mean boundary jumps fell from 0.94 to 0.35 mm.
The HueForge reference matched all 17.58 million visible pixel heights and physical
colors. Go regression coverage includes spatial inference, hue-independent
ordering, shared-shade grouping, returned-filament heights, family color guards,
strict final validation, settings migration, and export compatibility.
